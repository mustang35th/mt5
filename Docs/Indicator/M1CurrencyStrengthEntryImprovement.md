# M1エントリー：長中期の通貨強弱による遅れの改善案

- 作成日：2026/11/24（JST）
- 状態：検討案。条件・設定の変更は未実施
- 対象：通常版 `ZigZagElliot` と `ZigZagElliotMonitor` のM1エントリー判定

## 推奨する最初の比較

長中期を「売買方向の確認」、中短期を「エントリーのタイミング確認」に使う案を優先する。

通常版 `ZigZagElliot` では、既存の設定を次のように変更して比較できる。

```text
M1順位差の増減判定（M5履歴）
両方 → 中短期
```

この変更では、長中期・中短期の現在順位が売買方向と一致する条件を維持し、長中期の順位差の増減条件だけを外す。通常版はコード変更不要。モニター側は後述の対応が必要になる。

この案で改善を期待できるのは、長中期の順位方向が既に合っていて、増減方向の一致を待っている場面。長中期の順位方向そのものが反転待ちの場合は解消しない。

## 現行条件と遅れが生じる構造

### 通貨強弱の集計範囲

| 集計期間 | 使用する時間足 |
|---|---|
| 長中期 | MN1・W1・D1・H4・H1 |
| 中短期 | D1・H4・H1・M15・M5 |

長中期にはM1が含まれず、中短期にも上位足が含まれる。M1の価格変化と同時に順位やその増減が切り替わるとは限らない。

### M1の順位条件

順位差は「決済通貨順位 − 基軸通貨順位」で計算する。

| 項目 | BUY | SELL |
|---|---|---|
| 長中期の順位方向 | 順位差が＋1以上 | 順位差が−1以下 |
| 中短期の順位方向 | 順位差が＋1以上 | 順位差が−1以下 |
| 長中期の増減（両方モード） | 直近増減が上昇、または押し目例外 | 直近増減が下降、または戻り例外 |
| 中短期の増減（中短期・両方モード） | 直近増減が上昇 | 直近増減が下降 |

増減はM5の順位履歴を使う。順位差が横ばいの場合は、最後のゼロでない増減方向を引き継ぐ。

例えばBUY候補で長中期が次のように変化した場合、順位方向はBUYのままでも、増減判定は下降を維持する。

```text
長中期の順位差：+4 → +3 → +3 → +3
順位方向      ：BUY優勢
直近増減方向  ：下降を維持
```

この状態では、M1の価格が上昇へ戻っても長中期の増減条件を通過しない。実際の個別エントリーの遅れがこの条件によるものかは、その時点の判定結果で確認する。

### 既存の押し目・戻り例外

M1の増減判定が「両方」の場合、長中期に次の例外がある。

- BUY：現在順位差が＋4以上で、最後の順位差変化が−1。
- SELL：現在順位差が−4以下で、最後の順位差変化が＋1。
- データ取得状態・対象M5時刻・変化の根拠が整合していることが必要。

| BUYの例 | 長中期の例外判定 |
|---|---|
| `+5 → +4` | 許容 |
| `+5 → +4 → +4` | 許容。横ばいでも最後の変化−1を保持 |
| `+4 → +3` | 不許容。現在順位差が4未満 |
| `+6 → +4` | 不許容。最後の変化が−2 |

ここでの「許容」は長中期の追加条件を通ることだけを表す。中短期、波動、GMMA、スプレッドなど、他のエントリー条件も満たす必要がある。

M1の基本条件の最低順位差は1。例外に使う4や、候補一覧のREADY基準とは分けて扱う。

## 改善案の比較

| 優先順位 | 案 | 期待する変化 | 注意点・変更範囲 |
|---|---|---|---|
| 1 | 長中期は方向確認、中短期は方向と増減を確認 | 長中期の再拡大を待たずに候補を拾える場面が増える | 長中期が弱まり始めた場面も通る。通常版は既存の「中短期」設定で比較可能 |
| 2 | 長中期の押し目・戻り例外を調整 | 小さな順位差縮小を条件付きで許容する | 現在の「順位差4以上・逆行1」をパラメータ化し、許容範囲を検証する必要がある |
| 3 | 順位差に加えてスコア差を評価 | 順位が変わる前の強弱変化を評価できる可能性がある | 取得データ・閾値・記録方式の変更が大きい。早期化と成績改善は別途検証が必要 |

最初の比較では案1だけを変更し、他の波動条件や閾値は揃える。案2・案3は、案1の結果と除外理由を確認してから検討する。

## 通常版とモニターの対応差

### 通常版 ZigZagElliot

「M1順位差の増減判定（M5履歴）」には、次の選択肢がある。

| 設定 | 長中期の順位方向 | 中短期の順位方向 | 長中期の増減 | 中短期の増減 |
|---|---|---|---|---|
| OFF（順位方向一致のみ） | 必須 | 必須 | 不使用 | 不使用 |
| 中短期 | 必須 | 必須 | 不使用 | 必須 |
| 両方 | 必須 | 必須 | 必須（例外あり） | 必須 |

この表は、M1の通貨強弱エントリーフィルターが有効な場合の動作を示す。増減判定のOFFと、通貨強弱フィルター自体のOFFは異なる。

### ZigZagElliotMonitor

現行モニターは「両方」に固定されている。通常チャートの設定だけを変更しても、モニターの判定には反映されない。

モニターでも同じ比較を行う場合は、次の箇所を揃える必要がある。

| クラス | 対応が必要な内容 |
|---|---|
| `ZigZagElliotMonitorConfig` | 増減モードを選択可能にする |
| `ZigZagElliotMonitorEvaluator` | 「両方」固定の初期化チェックを見直す |
| `ZigZagElliotMonitorStrengthProvider` | 選択したモードに応じて必要な増減条件を設定する |
| `ZigZagElliotMonitorEntryDetails` | 事前判定と未達条件の表示を選択モードに合わせる |

通常版とモニターで共通のエントリー判定を使う方針を維持する。

## 比較・検証方法

同じ銘柄・期間・価格データで、「両方」と「中短期」を比較する。

| 記録項目 | 確認する内容 |
|---|---|
| 通貨強弱以外の条件が成立した時刻 | 基準となるM1候補時刻 |
| 長中期・中短期の現在順位差 | 順位方向が既に合っていたか |
| 各期間の直近増減方向・根拠時刻 | 増減条件だけで待っていたか |
| 対象M5時刻・データ取得状態 | DB更新待ちと条件不一致を区別する |
| 各方式の最初の成立時刻 | 何秒・何本早まったか、候補が増減したか |
| 成立後の最大逆行幅・最大順行幅 | 早期化によって不利な候補も増えていないか |

最大逆行幅・最大順行幅は、両方式で同じ観測時間とスプレッド等のコスト条件を使う。シグナル回数の管理も方式ごとに独立させ、片方の成立がもう片方の評価を消費しないようにする。

画面に「順位データ待ち」が出る場合は、条件の厳しさとは別に、DB側の更新時刻と取得待ち時間を確認する。順位差の増減が不一致の場合に、再取得間隔だけを短くしても条件そのものは変わらない。

追加した「値動き」列は、比較時の参考情報として利用できる。検証の初期段階では、値動きによる新しい必須条件を同時に追加しない。

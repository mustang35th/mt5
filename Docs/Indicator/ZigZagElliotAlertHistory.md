# ZigZagElliotAlertHistory

## 目的

Alert DBに保存されたM5アラートを指定Run・期間内で全件表示し、選択した一件の最新WaveをMT5チャートへ表示する履歴専用インジケーターです。v1.03では、元分析・補正分析・最終判定をDBから読み取り、通常のZigZagElliotに合わせた波動線・波動番号・情報表で確認できます。表示時にElliotAllの生成や波動の再分析は行いません。

ソースは`Indicators/ZigZagElliotAlertHistory.mq5`です。M5チャートに一つ追加して使用します。通常版とは独立したオブジェクト接頭辞を使い、終了時は履歴表示自身のオブジェクトだけを削除します。

## 入力パラメータ

| グループ | 画面の項目名 | 既定値・意味 |
|---|---|---|
| 01. Alert DB | Alert DBファイル名 | `mstng-zigzag-elliot-alert.sqlite` |
| 01. Alert DB | Commonフォルダを使用 | `true` |
| 02. アラート選択 | Run ID（0=条件に一致する最新Run） | `0`。通貨・期間・ENTRY条件に一致する最大Run IDを一つだけ選択 |
| 02. アラート選択 | 表示開始日（サーバー日付、0=制限なし） | `0`。指定日は午前0時から対象 |
| 02. アラート選択 | 表示終了日（当日を含む、0=制限なし） | `0`。指定日の翌日午前0時未満まで対象 |
| 02. アラート選択 | ENTRY成立のみ表示 | `false`。`true`では保存済み`is_entry = 1`のみ |
| 03. チャート表示 | 波動ラベルの上位足数 | `M15・H1・H4`。M5に加えて上位2足または3足 |
| 03. チャート表示 | 判定時価格・SL候補・FEを表示 | `true` |
| 03. チャート表示 | 時間足の情報表を表示 | `true` |

通貨はチャートの銘柄名との完全一致、アラート時間足はM5固定です。銘柄の接尾辞を自動変換しません。日付入力に時刻を付けても時刻部分は使用せず、日付単位で扱います。JSTからの変換は行いません。Run IDが明示された場合は、そのRunだけを検索し、該当なしでも別Runへ切り替えません。

例えば、GBPAUDのM5チャートでテスターのRun IDを指定し、表示開始日を`2026.08.01`、表示終了日を`2026.09.19`にすると、同じRunの期間内アラートだけを順に確認できます。Run IDは既存Viewerのアラート情報で確認できます。

## パネル配置（v1.01）

保存判定・採用SL候補・時間足情報表を左上、操作ボタンと選択情報を右上に表示します。上部全幅の背景帯は使用せず、左右それぞれに背景を配置します。

右上は「前後移動・件数」「再読込・発生位置へ」「採用分析・補正前／元分析・前後比較」の3段で、その下にRun・Alert日時・補正状態・メッセージを表示します。長い選択情報は省略表示し、全文はツールチップで確認できます。

チャート幅が1100px未満の場合は、操作欄を右上、保存情報をその下の左側に配置して重なりを防ぎます。リサイズ時は配置と情報表の高さ判定を更新します。保存判定・採用SL候補の値や、ボタンの機能は変更しません。

## 選択・前後移動

初期表示は、指定したRun・期間内の最初のアラートです。`current_bar_time`の昇順、同時刻はAlert IDの昇順とします。全アラートでも保存済みの`is_alert = 1`を対象とし、保存されなかった判定を補完しません。

- `← 前`・`次 →`：検索結果の一件前・一件後へ移動します。先頭・末尾の移動は無効です。
- 件数表示：現在の位置と検索結果の総件数を表示します。
- `再読込`：DBと一覧を再読込します。同じAlert IDが検索結果に残る場合はその選択を維持し、なければ期間内の最初のアラートへ移ります。
- `発生位置へ`：選択した発生足へチャートを移動します。価格履歴が不足している場合は取得を再試行します。

アラートを選び直すと、前の波動と価格線を消してから新しい一件を表示します。DB読取が失敗しても、前のアラートの波動を残しません。通常チャートの価格更新で選択アラートや保存分析を変更しません。

## 表示内容と補正切り替え

M5と指定された上位足の保存済み最新Waveを描画します。ポイント座標は`bar_time`と`rate`を使用し、保存時点の相対`bar_index`や現在の相場からの再分析値を使用しません。波動番号は上下・時間足別に配置し、未確定の最新ポイントは区別します。発生足の開始時刻に縦線を置きます。

| 保存状態 | 初期表示・切り替え |
|---|---|
| APPLIED | `採用分析`で補正後を表示。`補正前`・`前後比較`へ切り替え可能 |
| NONE | 元分析を採用して表示。前後比較は無効 |
| UNRECORDED | `元分析`のみ表示し、補正情報未記録を明示。採用SLを推測しない |
| INCOMPLETE | 補正データ不完全と理由を表示。利用可能な元分析を比較用として表示し、補正後として代用しない |

比較では補正後を実線、補正前を破線で重ね、番号・ツールチップでも分析区分を区別します。アラートを選び直すと、その記録の初期モードに戻ります。情報表には各時間足の保存情報を表示します。

チャートの高さに通常の情報表が収まらない場合は、各時間足を一行へ縮約し、比較時は補正後・補正前の方向と波動を同じ行に並べます。Count等の詳細は行のツールチップへ保持します。縮約した7行も収まらない場合は、チャートを縦に拡大する案内を表示します。

最終ENTRY判定と採用SL候補は、補正前表示へ切り替えても保存された採用結果を保持します。補正前のSL候補を併記する場合は比較用と明記します。FE価格線は表示中のM5保存分析を使い、比較時は前後を区別します。利用可能フラグがない価格を描画しません。

## 全件アラートラベル（v1.02）

指定した通貨・Run・期間・ENTRY条件に一致する全アラートの保存ラベルを取得します。通常版と同じMS Gothic・20pt、保存方向とENTRY成立状態に対応した色で表示します。例えば`▲3.1-1-3 [H1補正]`の文字列を保存値のまま使い、波動番号や補正表記を再生成しません。`▲/▼`はH1のWave方向で、アラートのBUY/SELLとは別です。

- 補正情報あり：`selected_alert_text`を表示します。補正前・前後比較へ切り替えても一覧文字は採用結果を維持します。
- 補正情報未記録：保存された`alert_text`へ`[元分析]`を付け、未記録と明示します。
- 保存文字・元分析M5始値・日時・補正メタデータが不足または不正：ラベルを表示せず、操作欄に保存値不足の件数を表示します。一覧内の位置は残るため前後ボタンで詳細を確認できます。

ラベルをクリックすると、そのAlert IDの波動線・情報表・保存判定・SL候補へ切り替えます。前後ボタンによる選択と同じ処理を使います。選択中の発生足には縦線を表示し、波動線と情報表は一件分だけ描画します。

表示基準は発生足の`current_bar_time`と元分析M5の`current_open`です。現在のチャート表示範囲内のラベルを描き、スクロール・拡大縮小・リサイズ時に再配置します。密集箇所は文字の表示位置だけ上下へずらし、保存位置と文字を点線で結びます。極端に密集し空き領域がない場合は重なりが残ります。保存時刻・価格は変更しません。

全件表示の検索ではラベル用の保存値だけを一括読込し、詳細な時間足・波動ポイントは選択時に取得・検証します。保存ラベルが表示できても、詳細分析の保存データが不完全なら、選択後は従来の不完全状態として扱います。全件の発生時刻と選択Waveを含む価格履歴を要求し、履歴不足の場合は状態を表示します。

文字色は通常版と同じくBUYが青、BUYのENTRY成立が水色、SELLが赤、SELLのENTRY成立がマゼンタです。価格線・時間足情報表の表示設定によらずラベルを表示します。

## ツールチップ

| 対象 | 内容 |
|---|---|
| 波動番号 | 時間足、分析区分、分析方向、主波・副次波、保存時点のWave確定状態、ポイント日時・価格、F/FE、pips差 |
| 波動線 | 分析区分、始点・終点の日時・価格、値幅pips |
| アラートラベル | 採用方向・ENTRY結果、MN1〜M5の分析方向／EMA200方向・主波／副次波・確定状態、補正方向、判定JST／Server日時。159文字以内で表示 |
| 発生位置の縦線 | 発生足・判定日時、ENTRY結果、補正内容、判定時価格、採用SL候補、Run・Alert ID |

改行と単位を付け、未保存・利用不可の値は`—`として表示します。波動線・番号のツールチップは表示中の補正前後に対応します。全件アラートラベルは比較モードにかかわらず採用分析を表示し、アラートの最終判定は常に保存結果を表示します。

アラートラベルの`JST`はDBに保存された`jst_time`を使用します。`SV`と同じ判定時刻の日本時間であり、M5足の開始時刻とは区別します。JSTが未記録の場合は`—`とし、現在のサーバー時差で再換算しません。

v1.03の全件アラートラベルの例（値は表示例）：

```text
採用 BUY/ENTRY
足 分析/EMA 波動
MN1 B/— 3.1確
W1 B/B 3.1確
D1 B/B 1.1未
H4 B/B 3.1未
H1 B/B 3.1未
M15 S/B 2.1未
M5 B/B 3.1未
H1補正 S→B
JST 09/11 21:35
SV 09/11 15:35
```

- `B`＝BUY、`S`＝SELL。分析は保存された`is_buy`、EMAは保存された`is_ema200_buy`／`is_ema200_sell`から表示します。MN1のEMAは常に`—`です。両フラグが同値・欠損・不正な場合も`—`とし、SELLと推定しません。
- 波動は`主波.副次波`（副次波なしなら主波のみ）、末尾の`確`／`未`は最新Waveの確定／未確定です。未記録値は`—`です。
- `APPLIED`は全7足を補正後テーブル、`NONE`は元テーブルから読みます。補正後の欠損を元分析で補完しません。補正情報未記録は見出しを`元分析(未記録)`として元テーブルから読みます。再分析・DB更新はありません。
- 日時は保存された判定時刻で、年・秒を省略します。159文字超過時はSV行、副次波の順に省き、7足の分析方向・EMA方向・主波・状態とJSTを残します。異常に長い波動値はセル内で`…`とし、末尾の行を途中で切りません。長いENTRY結果は保存済みENTRY成立フラグの要約へ置き換えます。
- 通常の`ZigZagElliot`のDB表示でも同じ形式です（v1.48のH1チャートではMN1〜H1の5足を表示）。通常ラベルと重なる場合は既存ラベルへ設定し、DB表示の解除時に元へ戻します。

## 価格履歴と再現範囲

ローソク足はMT5の価格履歴を使います。保存元Runのサーバーと現在の接続先が異なる場合は画面へ明示します。履歴の非同期取得を最大15回確認し、足が見つからない場合は価格履歴不足を表示します。対象時刻が存在しない場合、別の時刻の足を発生足として代用しません。

履歴表示中は発生位置への移動時に自動スクロールを無効にし、インジケーター終了時には追加前の設定へ戻します。ズームや手動スクロールで保存分析を変更せず、文字位置を再配置します。

現在のAlert DBには各時間足の最新Waveと直近OHLCのみがあり、連続したローソク足・全Wave・EMA/GMMA曲線の全履歴は保存されていません。したがって過去の全画面を完全再現する機能ではありません。確定後のローソク足と、アラート当時の未確定足の保存値は異なる場合があります。判定時価格は参照価格、SLは分析時の候補として表示し、約定価格や実際の注文SLとは区別します。

## 読取と整合性

`SqliteDatabase.openReadOnly()`を使い、テーブル作成・スキーマ移行・DB更新は行いません。ファイルが存在しない場合も作成しません。元分析・補正分析・メタデータを一つの読み取りトランザクションで取得します。

ポイントの件数・順序・所属時間足・最新ポイント・補正方向・採用SL等の整合性を検証し、不足や不整合を表示状態に反映します。元分析が不完全な場合は元波動を描画しません。保存・メール・注文・Signal Count更新の処理は呼び出しません。

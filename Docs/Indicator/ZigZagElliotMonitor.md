# ZigZagElliotMonitor

- バージョン：1.09
- 更新日：2026/11/20（JST）
- 対象：通常チャート。初期版はGMO対象18通貨ペア・M1固定

複数通貨ペアを順番に監視し、現行ZigZagElliotのM1エントリー条件が新しく成立した通貨ペアを、同じMT5の別チャートで開くインジケーターです。監視元の通貨ペア・時間足にかかわらずM1を分析します。

## 使用方法

1. 監視用の通常チャートに `Indicators/ZigZagElliotMonitor.ex5` を追加します。初期版は1つのMT5につき1インスタンスで使用してください。
2. 通貨強弱を収集する既存の仕組みを稼働させ、参照するDB設定を合わせます。Monitor自身は順位データを作成しません。
3. 各通貨の確認を待ちます。自動表示がONなら、初回のENTRYもM1チャートを開く対象になります。
4. 新規チャートへ既定の `ZigZagElliot-4.tpl` を適用要求します。その後も、まだ処理していないENTRYを自動表示します。

成立を待たずに確認するときは、各通貨ペアの右端にある **「表示」** を押してください。監視・自動表示がOFFでも操作できます。

既定のテンプレート入力値は `\Profiles\Templates\ZigZagElliot-4.tpl` です。現在のMQL5フォルダ内の `Profiles/Templates` にあるテンプレートを指定しています。別のMT5へ移すときは、インジケーター・依存ファイル・テンプレートも用意してください。先頭 `\` の探索先と、適用APIの非同期動作は [ChartApplyTemplate公式仕様](https://www.mql5.com/en/docs/chart_operations/chartapplytemplate) に基づきます。

## 監視対象

既存の `SymbolNameInfoAll.setGmo()` にある対象フラグを使用します。`[G]` はGMO対象ペアの印であり、接続先がGMOであることを示すものではありません。

`AUDJPY`、`AUDNZD`、`AUDUSD`、`CADJPY`、`CHFJPY`、`EURAUD`、`EURCHF`、`EURGBP`、`EURJPY`、`EURUSD`、`GBPAUD`、`GBPCHF`、`GBPJPY`、`GBPUSD`、`NZDJPY`、`NZDUSD`、`USDCHF`、`USDJPY`。

銘柄の正規名を優先し、接頭辞・接尾辞付きの実銘柄は基軸通貨・決済通貨を確認して解決します。同じ最短名候補が複数ある場合や該当銘柄がない場合はERRORにし、別銘柄へ推測で置き換えません。対象銘柄と名前の候補は気配値表示へ選択します。未選択銘柄では属性を取得できない場合があるためです。[SymbolInfoString公式仕様](https://www.mql5.com/en/docs/marketinformation/symbolinfostring)

将来の28通貨対応に備え、対象の構築を判定・描画から分離しています。初期版の入力設定から28通貨への切替はできません。

## M1エントリー条件

既存のM1専用判定クラスを使用します。初期版では以下を固定し、監視側に別の条件設定を増やしていません。

| 項目 | 条件 |
|---|---|
| 元の売買方向 | D1・M5・M1が一致 |
| 方向補正 | H4・H1・M15のうち逆方向1足まで。再分析後の方向・条件も確認 |
| エリオット波動 | 採用するM5・M1が、それぞれ主波の第1波または第3波 |
| M1の波方向 | BUYは上昇、SELLは下降 |
| GMMA | M1のトレンド・クロス両カウントがBUYは＋2以上、SELLは−2以下 |
| ZigZag | M1の最新ポイントが追加途中ではない |
| 通貨強弱 | 長中期・中短期ともBUYは順位差＋1以上、SELLは−1以下 |
| 順位差の増減 | 両期間ともBUYは上昇方向、SELLは下降方向 |
| スプレッド | 3 pips以下 |
| シグナル回数 | 元M1基準時刻と売買方向が同じシグナルの初回のみ |

順位差は「決済通貨順位 − 基軸通貨順位」です。増減はM5履歴を使い、横ばいでは直前の増減方向を維持します。両期間の現在順位・増減履歴が必要です。方向不明は不成立、データ未取得は待機です。

EMA200の方向・距離、MN1・W1の方向一致、M15の波動番号、FE上限はM1の条件に追加していません。通常版の仕様は [ZigZagElliot.md](ZigZagElliot.md) を参照してください。

## 更新方法と表示

1秒タイマーで順番に確認し、1イベントにつき最大1通貨を処理します。各通貨はM1新バーごとに判定し、取得待ちは最短5秒間隔で再確認します。通常版のタイマー監視と判定時刻が同一になる保証はなく、M1の途中だけ成立する条件をすべて検出する方式ではありません。

今回のM1に対応するM5枠を固定します。分析中にM1・M5が切り替わった場合、気配が30秒を超えて古い場合、分析データが不足する場合は結果を採用せず、シグナル回数も消費しません。分析中の通常のティック変動は許容します。既存の方向補正内にある入力検証は維持しています。

通貨強弱の必要条件を先に確認し、候補だけ波動分析へ進みます。オシレーターハンドルと通貨別DB取得先は必要になった通貨だけ生成して再利用し、ラベルは変更項目だけ反映します。

価格履歴が同期済みでも、生成直後の指標はまだ計算中の場合があります。Stochastic短期・中期・長期、GMMA、ATR、EMA200の計算済み本数と最新値を確認してから分析します。未準備の通貨は「待機」とし、対象時間足・指標名をツールチップへ表示します。待機中はハンドルを保持し、次のタイマーで再確認します。月足EMA200は既存仕様どおり確認対象から除きます。

| 表示列 | 内容 |
|---|---|
| 通貨ペア | 正規名とGMO対象の印。実銘柄名はツールチップ |
| 判定 | ENTRY・強弱未達・M1未達・順位待ち・指標待ちなどの短い理由。ENTRYを上位、その中では通貨ペア順 |
| 方向 | 現在のENTRYのBUY／SELL。不成立・待機は「—」 |
| 直近成立（JST） | 最後にENTRYを確認した時刻。後の不成立でも保持 |
| 表示結果 | 最後の自動・手動表示処理の結果。手動操作には「手動」を付記 |
| チャート | 各通貨ペアのM1チャートを手動で開く「表示」ボタン |

日時は `YYYY/MM/DD HH:MM:SS` に統一し、元のSRV時刻・判定詳細はツールチップに表示します。成立時刻はMonitorが確認した時刻であり、元の波動の基準時刻とは異なります。

| 状態 | 意味 |
|---|---|
| WAIT／待機 | 初期準備、価格・順位・増減履歴の取得待ちなど。再確認対象 |
| 不成立 | 今回のM1確認が完了し、ENTRY条件に達していない。同じシグナルの確認済みも含む |
| ENTRY | 今回のM1確認で初回成立を検出 |
| エラー | 銘柄解決や読み取りなどのエラー。詳細をツールチップに表示し、再確認 |

各行の判定列では、待機の理由を「順位待ち」「履歴待ち」「指標待ち」「気配待ち」「分析待ち」「補正待ち」などへ分けます。不成立は「強弱未達」「M1未達」、同じシグナルの確認後は「確認済み」と表示します。確認中の通貨は「確認中」、まだ確認していない通貨は「未確認」です。前のM1枠の結果には「前回」を付けて色を抑え、現在足の判定と区別します。詳細な対象時間足・指標名・判定理由・処理時間はツールチップに保持します。

下部は、今回のM1進捗・処理状況・最終確認の3行です。

- **対象M1／判定済み**：最後に受信したサーバー時刻のM1枠を全通貨共通の集計対象とし、その足の判定を完了した数を表示します。強弱未達やM1未達も完了に含み、ENTRY数はその足の成立だけを数えます。画面外の通貨も集計し、次のM1枠へ移ると前の足の件数を引き継ぎません。
- **確認中／直前**：実際に確認を開始する通貨名を表示し、完了後は直前の通貨名と処理時間（ms）へ切り替えます。完了済みや再試行間隔内のスキップでは更新しません。計測は開始表示の更新後から順位取得・履歴／指標準備・波動判定などの確認終了までで、チャート起動・テンプレート適用時間は含みません。
- **待機・未確認・エラー**：対象M1枠でまだ確認していない通貨、確認したがデータなどを待つ通貨、エラーの通貨を区別します。履歴が未取得でM1時刻が0の場合も、確認を試みた共通M1枠を使って待機・エラーへ分類します。確認中は別枠で数えます。
- **全体状態**：全対象が完了すれば「次のM1足待ち」、未確認が残れば順次確認、取得待ちなどが残れば再確認待ち、監視OFFなら「監視停止」と表示します。
- **最終確認／表示枚数**：最後に確認を試みたJST時刻と管理中チャート枚数を表示します。起動／監視再開後の累計確認済み数、元のSRV時刻、表示領域不足などはツールチップで確認できます。

進捗は保持済みの状態から集計し、追加の価格取得や波動分析は行いません。実確認の開始・終了、対象M1枠の変更、ボタンや画面構成の変更に合わせて描画値を更新し、変更がある場合だけ再描画します。チャートが低い場合は表示行数を調整しますが、監視処理と進捗集計は全対象で続けます。

## ボタンとチャート表示

- **各行の「表示」**：エントリー成立や監視・自動表示のON／OFFに関係なく、その通貨ペアのM1チャートを表示して前面に出します。成立時刻・シグナル回数・初回確認状態は変更しません。通貨名に紐付くボタンのため、ENTRYによる並び替えがあっても押した通貨を対象にします。
- **監視ON／OFF**：OFF中は分析を停止し、表示を保持します。再開後は現在の足を確認し、自動表示がONなら未処理のENTRYを表示します。シグナル回数は保持し、同じシグナルを開き直しません。
- **自動表示ON／OFF**：OFFでも監視・成立記録は続けます。ONへ戻しても、OFF中の成立を遡って開きません。
- 同じ実銘柄のM1チャートが既にあれば「既存表示」とし、テンプレートを上書きしません。監視元チャートは再利用対象から除きます。
- 新規チャートだけに指定テンプレートを適用します。「テンプレ受付」は要求の受付であり、描画完了の確認ではありません。
- 自分が今回の稼働中に開いたチャートだけを上限に数えます。手動・自動で枠を共有し、上限の既定値は18枚です。既存チャートは枠を消費せず、上限でも再利用できます。
- 手動でチャートを閉じると枠が空きます。自動表示では同じシグナルを開き直しません。「表示」ボタンは同じ通貨を再度開けます。
- 上限・起動失敗・テンプレート失敗になったENTRYは自動再試行しません。テンプレート失敗でも作成したチャートを残し、枚数に数えます。
- インジケーターを外しても開いたチャートは残します。履歴・重複管理・所有枚数は今回の稼働中だけ保持し、再初期化ではリセットします。

## 実装範囲と確認状況

新規エントリーポイントは `Indicators/ZigZagElliotMonitor.mq5` です。制御・設定・判定・通貨状態・通貨強弱取得・チャート管理・結果型を `Include/Mstng/Indicator/ZigZagElliotMonitor`、描画を `Include/Mstng/Draw/DrawZigZagElliotMonitor.mqh` に分けています。既存判定側にはM1補正分析の準備失敗を読み取る状態を追加し、Monitorで再確認できるようにしています。既存の売買条件は維持しています。

Monitorから注文・メール・成立CSV／DB保存は行いません。新規チャートへ適用するテンプレート内の各インジケーターは、そのテンプレート設定で動きます。ストラテジーテスターは対象外です。

MetaEditorによるコンパイルと、ソースから抽出したロジックにAPI代替を与える境界検証を実施しています。実相場での監視・チャート自動起動・手動表示ボタンの実画面操作・テンプレート適用完了は未確認です。

検討時の資料：[機能案](ZigZagElliotMonitorProposal.md)／[クラス図案](ZigZagElliotMonitorClassDiagram.md)。これらには今回の初期版に含めていない案もあります。

## 変更履歴

- 1.09：「自動表示時にチャートを前面へ」の初期値をONに変更。自動表示時は新規・再利用した対象チャートの前面表示を要求します。
- 1.08：今回のM1足の判定進捗、確認中／直前の通貨、処理時間、待機・未確認・エラー件数を追加。判定列の理由を具体化し、前の足の結果を区別します。売買条件・シグナル回数・分析頻度は維持します。
- 1.07：チャート表示の最大枚数（手動・自動）の初期値を5枚から18枚へ変更。設定可能範囲は1～28枚のままです。
- 1.06：自動表示がONなら、起動・監視再開後の初回ENTRYもチャート表示対象に変更。「初回確認」による表示抑止を解除し、同じシグナルの重複防止・既存チャート再利用・枚数上限は維持します。
- 1.05：通常表示でも空の案内ラベルが先頭通貨へ重なる問題を修正。案内は監視対象0件または表示領域不足で行を表示できない場合だけ作成し、通常表示へ戻ると削除します。
- 1.04：ZigZagの取得上限300本より同期済み履歴が少ない場合、実在する履歴本数に要求を縮小します。例えば月足237本では237本を取得し、300本以上の履歴では従来の上限を維持します。未同期・未取得の履歴は既存の取得要求で構築を促し、準備後に再確認します。高値・安値の取得本数が異なる場合は、時系列を取り違えないよう不採用にします。
- 1.03：各通貨ペアへ手動の「表示」ボタンを追加。エントリー条件・監視／自動表示のON／OFFに依存せずM1を表示して前面に出します。新規チャートへ設定テンプレートを適用し、既存M1は再利用します。枚数上限は自動表示と共用です。
- 1.02：指標ハンドル生成後の計算準備を確認し、未準備なら分析開始前に待機。少ない月足履歴では既存の取得方式と同じく参照本数を縮め、月足EMA200は対象外としました。準備待ちは成立回数を消費しません。
- 1.01：チャート一覧の終端 `ChartNext() == -1` を先に判定。終端の `ERR_CHART_NOT_FOUND` は直前チャートの存在確認後に受け入れ、途中消失・別のエラー・監視元不在は失敗として扱います。取得失敗ログへAPI名・チャートID・エラー番号・取得件数を追加しました。

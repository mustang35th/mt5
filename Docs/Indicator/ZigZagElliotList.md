## 2. 目的と機能範囲

主要28通貨ペアを複数時間足で分析し、方向一致条件を満たす通貨をBUY・SELL別に表示する。各行には波動、EMA方向、Fibonacci比率、表示用優先度を表示する。M15では優先度欄を不一致情報へ置き換え、条件別の4テーブルに分類する。

- 一覧モードはCHART、D1固定、H4固定、H1＋M5独立2段の4種類。
- 分析および時間足列はMN1から一覧基準足までを使用する。一致条件を調べる範囲とは区別する。
- チャートオブジェクトで描画する。1本の非表示バッファを持ち、描画種別は`DRAW_NONE`。
- 自動発注・決済は行わない。
- DB保存を有効にした場合、テスターのH1で28通貨のMTF_3in3 Alertを収集する。

## 3. 対象通貨と時間足

### 3.1 対象通貨

`SymbolNameInfoAll.setAll()`の次の28通貨を対象とする。入力による通貨選択はない。

| グループ | 通貨ペア |
|---|---|
| JPY | USDJPY、EURJPY、GBPJPY、AUDJPY、NZDJPY、CADJPY、CHFJPY |
| USD | EURUSD、GBPUSD、AUDUSD、NZDUSD、USDCAD、USDCHF |
| GBP | EURGBP、GBPAUD、GBPNZD、GBPCAD、GBPCHF |
| EUR | EURAUD、EURNZD、EURCAD、EURCHF |
| AUD | AUDNZD、AUDCAD、AUDCHF |
| NZD | NZDCAD、NZDCHF |
| CAD | CADCHF |

DB有効時は実シンボル名を解決する。標準名を優先し、存在しない場合は標準名を含み、基軸通貨・決済通貨が一致する候補のうち最短名を選ぶ。全対象を解決できなければ初期化に失敗する。この名前解決はDB無効時には実行しない。

### 3.2 時間足の系列

```text
MN1 → W1 → D1 → H4 → H1 → M15 → M5 → M1
```

上位1足・上位2足とは、この系列内の直上の足を指す。M30やH2などは範囲生成の対象外。CHARTでは一致判定の開始が原則D1（M15はMN1、H1は選択条件による）なので、対応する一覧基準足はD1・H4・H1・M15・M5・M1。CHARTのW1・MN1はD1からの範囲を生成できず、初期化エラーになる。

## 5. 一覧モードと抽出条件

「方向」は原則として各`Elliot.isBuy`の分析方向を指す。最新Waveの上昇・下降方向やEMA方向とは別の値である。以下の「＝」は分析方向の一致を表す。

EMA200方向は共通分析`ELLIOT_MN1_V7`の確定足による2回連続判定を使用する。BUYは`Close[1] > EMA200[1]`かつ`EMA200[1] > EMA200[2] > EMA200[3]`、SELLは不等号を反転した条件で、その他は`NONE`。同値を含む場合や直近2回の方向が異なる場合はNONEとし、形成中の足は使わない。EMA期間200は維持し、傾きはshift 1と3、上昇・下降回数は直近2区間を記録する。以下のテーブル分類・時間足間の一致条件はこの方向を参照する。

| 値・モード | 基準足 | 抽出条件 | 実効ソート |
|---|---|---|---|
| 0：CHART | チャート足 | H1は5.3、M5は5.5、M15は5.6。それ以外はD1から基準足まで全方向一致 | 入力値。ただしH1は専用順、M15は4分類・NONE優先後に適用 |
| 1：D1固定 | D1 | 選択したD1条件 AND D1 EMA200同方向 | D1専用順 |
| 2：H4固定 | H4 | 選択したD1条件 AND D1＝H4 | ENTRY優先度 |
| 3：H1＋M5独立2段 | 上段H1／下段M5 | 上段は5.3、下段は5.5のM5条件 | 上段H1専用順／下段ENTRY優先度 |

H4固定には、D1固定のD1 EMA200必須条件を追加しない。CHARTのD1もD1固定とは異なり、W1との一致やD1 EMA200一致を必須にしない。

### 5.1 D1条件

| 値 | 条件名 | 条件 |
|---|---|---|
| 0 | W1＝D1 | W1＝D1 |
| 1 | MN1＝W1＝D1 | MN1＝W1＝D1 |
| 2 | W1＝D1 ＋（MN1 または W1 EMA200） | W1＝D1 AND（MN1＝D1 OR W1 EMA200がD1方向） |

### 5.2 D1 EMA200必須条件

D1固定および全H1一覧では、D1の分析方向とD1 EMA200方向の一致を必須とする。BUYならEMAがBUY、SELLならEMAがSELLであることを要求する。NONE・逆方向・BUY/SELL競合・ラベルや時間足の不整合は通過させない。

この条件はEMA200との距離条件ではない。D1-S/A/Bの表示ランクとも別に判定するため、D1-SでもD1 EMA200が逆方向なら表示対象外となる。

### 5.3 H1条件

すべてのH1モードに次を適用する。

```text
H1表示対象 = 選択したD1条件
           AND D1分析方向とD1 EMA200方向の一致
           AND 下表のH1条件
```

| 値 | 条件名 | 追加条件 |
|---|---|---|
| 0 | D1＝H4＝H1 | D1＝H4＝H1 |
| 1 | MN1～H1すべて一致 | MN1＝W1＝D1＝H4＝H1 |
| 2 | W1～H1一致 ＋（MN1 または W1 EMA200） | W1＝D1＝H4＝H1 AND（MN1＝H1 OR W1 EMA200がH1方向） |
| 3 | D1条件 ＋（H4 または H1） | D1＝H4 OR D1＝H1 |

初期値ではW1・D1・H4・H1の一致と、D1 EMA200同方向が必要となる。値3はD1基準の方向へ分類し、H1が逆方向でもH4がD1と一致すれば表示可能。ENTRY判定はD1とH1が一致する場合H1、そうでなければH4を使用する。

### 5.4 H1＋M5独立表示

上段は`H1 ENVIRONMENT`、下段は`M5 INDEPENDENT`。下段は上段の抽出結果で絞り込まず、独自に5.5のM5条件を判定する。同一通貨が両段の対象となった場合、各段の行方向に応じてシンボル欄をBUYは青系、SELLは赤系の背景で強調する。重複判定自体は両段の方向一致を要求しない。

上段の描画高さに応じて下段を配置する。各描画器の最小パネル幅は900。両段のENTRY凡例および上段H1の次点候補パネルは非表示。

### 5.5 M5の抽出条件（v1.36）

CHARTのM5と独立2段の下段M5に、v1.35のA案とv1.36の5足EMA200一致を固定適用する。

「D1条件」「H1条件」の入力はM5抽出には適用しない。独立2段の上段H1、D1固定、H4固定、CHARTのM5以外の抽出条件は、それぞれの既存仕様に従う。

```text
M5表示対象 = D1＝M15＝M5
           AND（H4＝M5 OR H1＝M5）
           AND D1・H4・H1・M15・M5のEMA200がすべてM5分析方向に一致
```

BUYはD1・M15・M5の分析方向がすべてBUYで、H4・H1の少なくとも片方がBUY、かつ5足のEMA200方向がすべてBUY。SELLはすべて逆とする。H4・H1の分析方向が両方逆の場合、D1またはM15がM5と逆の場合は表示しない。

| 時間足 | 分析方向（`Elliot.isBuy`） | EMA200方向 |
|---|---|---|
| D1 | M5と同方向必須 | M5と同方向必須 |
| H4 | H4・H1の少なくとも片方がM5と同方向 | M5と同方向必須 |
| H1 | H4・H1の少なくとも片方がM5と同方向 | M5と同方向必須 |
| M15 | M5と同方向必須 | M5と同方向必須 |
| M5 | BUY／SELLの基準方向 | 自身の分析方向と一致必須 |

たとえばBUY候補では、H4の分析方向がSELLでもH1がBUYならA案は成立する。ただし、その場合もH4のEMA200はBUYであることを要求する。H1の分析方向だけがSELLの場合も同様に、H1のEMA200はBUYを必須とする。

分析成功およびD1・H4・H1・M15・M5すべての最新Wave・Pointの存在は引き続き必須。ORの片方のデータが欠けた場合も未準備とする。MN1・W1の分析方向およびEMA方向は抽出条件に加えない。

EMA条件は既存のEMA200 BUY/SELLフラグと`getBuySellLabel()`を使用する。5足のうち1足でも逆方向・NONE・BUY/SELL競合・ラベル不整合・オシレーターやEMAの時間足不整合があれば表示対象外。EMA同士が一致していてもM5分析方向と逆なら通過させない。EMAの価格値や時間足間の上下順序、距離条件は追加しない。EMA不成立自体は分析エラーとして数えない。

一覧タイトルの条件表示は`D1=M15=M5&(H4|H1)&EMA5`。`EMA5`はD1・H4・H1・M15・M5のEMA200方向一致を表す。追加inputや旧条件への切替は設けない。既存のM5表示にも再読み込み後に適用される。共有判定の既定値は従来の全足一致を維持し、ListのM5で新ルールを明示指定する。

READY判定・並び順・Alert・EA・評価周期は変更しない。たとえば5足EMAが一致して表示された通貨でも、既存READY判定の波動やGMMA等の条件が不足すればREADY以外になる。H4/H1一致状況の新しい列や優先順は追加しない。

### 5.6 M15の抽出条件と4分類（v1.42）

CHARTのM15では、MN1・W1・D1・H4・H1・M15の6足の`Elliot.isBuy`の多数派を共通の基準方向とする。6足中5足以上が同じ方向の場合だけ対象となるため、同数の場合や逆方向が2足以上の場合は表示しない。元の`Elliot.isBuy`は変更しない。

EMA200はW1・D1・H4・H1・M15の5足を、同じ基準方向に対して判定する。4足以上の一致を要求し、残り1足は逆方向または正常なNONEを許容する。MN1のEMA200は判定対象外。

| テーブル順 | 分類 | isBuy：MN1～M15 | EMA200：W1～M15 |
|---|---|---|---|
| ① | 全一致 | 6足一致 | 5足一致 |
| ② | isBuyが1足逆 | 5足一致＋1足逆 | 5足一致 |
| ③ | EMA200が1足不一致 | 6足一致 | 4足一致＋1足が逆またはNONE |
| ④ | 両方が1足ずつ不一致 | 5足一致＋1足逆 | 4足一致＋1足が逆またはNONE |

各通貨は1つのテーブルだけに表示する。④はisBuyとEMA200の不一致が同じ時間足でも、異なる時間足でも対象となる。

たとえばMN1・W1・D1・H4・H1がBUY、M15だけSELLで、W1～M15のEMA200がすべてBUYなら②のBUY側に表示する。M15自身やMN1・W1のisBuyだけが逆でも許容する。isBuyがBUYで全一致していても、EMA200がSELLで全一致なら対象外。EMA200が3足一致＋1足逆＋1足NONE、または3足一致＋2足NONEの場合も対象外。

正常なNONEとはEMA200のBUY／SELLフラグが両方falseで、方向ラベルも`NONE`の状態を指す。BUY／SELLのフラグ競合、フラグとラベルの不整合、オシレーターやEMAの時間足不整合は許容しない。分析成功とMN1からM15までの最新Wave・Pointの存在を必須とし、データ未取得・計算失敗をNONEとして扱わない。EMA条件の不成立自体は分析エラーとして数えない。

「D1条件」「H1条件」の入力はM15抽出には適用しない。追加inputや旧条件への切替は設けず、CHARTのM15へ固定適用する。H1・M5・D1・H4の一覧条件、ZigZagElliotのAlert・EA判定は従来どおり。

## 6. 画面表示

BUY・SELLを左右のパネルに分け、各方向の件数を表示する。基本色はBUYがAqua、SELLがHotPink。

M15は①全一致、②isBuyが1足逆、③EMA200が1足不一致、④両方が1足ずつ不一致の順で縦に4テーブルを配置する。各テーブルは多数派方向のBUYを左、SELLを右に分けて件数を表示する。0件のテーブルは見出しだけを残し、後続テーブルの位置は描画高さに合わせて更新する。更新時刻は先頭テーブルだけに共通表示する。

M15ではENTRY欄を`不一致`に変更し、上段に`isBuy逆:H1`、下段に`EMA逆:W1`または`EMA NONE:H1`のように表示する。一致している項目は一致と分かる表示にする。元の波動・Fibonacci情報を維持し、不一致の時間足セルは逆方向を黄色、NONEを灰色で区別する。MN1のEMA欄は判定対象外を示す`-`とする。基準方向とM15自身の分析方向が異なる場合もあるため、この4テーブルではREADY等のENTRY状態を表示しない。

初回描画前に一度だけ、再起動やテンプレート読み込みなどで残った当一覧の旧描画オブジェクトを除去する。対象はメインチャート上の`FixedMstngZzElList_`で始まるオブジェクトで、以前の独立2段表示の下段やM15の4テーブルも含む。当一覧がチャートに1つだけと確認できた場合に実行し、複数ある場合や件数を確認できない場合は、他インスタンスの描画を保護するため除去しない。

| 項目 | 内容 |
|---|---|
| タイトル | 一覧基準足、対象・分析・エラー等の集計。2行目に更新間隔・最終更新・次回目安（JST） |
| シンボル | 通貨名。独立2段では両段に表示される通貨を各行の方向色の背景で強調 |
| ENTRY／D1条件／不一致 | 表示足とソート方式に応じた優先度またはD1-S/A/B等。M15は不一致欄でisBuy逆・EMA逆・EMA NONEの時間足を表示 |
| 時間足列 | MN1から基準足までの各足の波動、EMA方向、Fibonacci比率 |
| H1のEMA3 | H1方向に対するH1・H4・D1のEMA200一致の参考表示 |

v1.40から、タイトル2行目に次の形式で更新予定を表示する。時刻は既存の日本時間変換を使い、末尾に`（JST）`を付ける。

```text
M15 ｜ 更新：5分ごと ｜ 最終：14:30 ｜ 次回目安：14:35（JST）
```

- 更新間隔はコントローラーが実際に使用する更新基準足から取得する。通常チャートは5分、M15テスターは15分、H1＋M5独立表示は両段とも5分。
- 最終は28通貨の分析が完了した時点の時刻。初回の分析未完了時は`--:--`、その後に分析未完了となった場合は前回完了した表示を保持する。
- 次回目安は今回処理した更新基準足のバー開始時刻に1周期を加えた時刻。たとえば通常M15で14:33に初回更新した場合は14:35となる。初回未完了時は`--:--`。
- 次回時刻は新規バーの検出と分析完了までの目安であり、固定時刻での再描画を予約するものではない。更新周期・2秒タイマー・再試行処理は変更しない。
- 従来のJST／サーバー時刻の年月日時分秒とLIVE／TESTERは、タイトルのツールチップに保持する。

波動は方向ラベルとElliottラベルを連結する。再カウント前の主波ラベルが現在の主波と異なる場合は、`▼1.iii[3]`のように`[元ラベル]`を併記する。現在または元の主波が空、または同じラベルなら併記しない。未確定Waveは先頭に`【未】`、補完ポイントは末尾に`★`を付ける（例：`【未】▼1.iii[3]★`）。取得できない波動は`-`。表示中の全時間足列に適用し、抽出・並び順・判定用ラベルは変更しない。

元ラベル付きの波動が列幅を超える場合、そのセルだけ文字幅を計測して10ptから最小6ptまで縮小する。短い表示へ変わったときは通常の10ptへ戻す。列幅・売買色・EMAとFibonacciの表示は維持する。

Fibonacciは元の波番号が1以下なら表示せず、偶数は`F`、奇数は`FE`を付けて小数1桁で表示する。不正な値は表示しない。時間足セルのツールチップには波動・ポイント・比率・値幅・バー数・時刻・価格等の詳細を表示する。

`EMA3 OK`は3足一致、`EMA3 NG`は不成立、`EMA3 ?`は分析結果不足を表す。これは一覧の追加フィルタではない。H1条件の値3でH1がD1と逆方向なら、表示対象でも`EMA3 NG`になり得る。

H1単独表示でH1条件が値2の場合、`NEXT H1 4/5`にあと1条件で方向一致する次点候補を表示する。次点候補にも共通D1条件とD1 EMA200条件を要求する。独立2段では次点候補を表示しない。

## 7. 並び替えと表示用優先度

### 7.1 ENTRY優先度

`Mtf3In3EntryPriorityDecision`が副作用なしで計算する表示用の順位である。M15の4テーブルではREADY等を画面表示せず、不一致情報を表示する。M15でENTRY優先度の並び順を選択した場合や専用ソートが同順位の場合は、従来のM15分析方向を基準に計算した順位を並び替えに使用する。

| 優先順 | 表示 | 条件 |
|---|---|---|
| 1 | READY | 対象波動が揃い、副条件9項目すべて成立 |
| 2 | NEAR | 対象波動が揃い、副条件が1項目だけ未達 |
| 3 | SETUP | 対象波動が揃い、副条件が2項目以上未達 |
| 4 | ALIGN | 対象波動が未完成 |
| 5 | ERROR | 判定に必要な分析結果が不足 |

対象波動は最新ポイントのElliottラベルが`1`または`3`。H1はH1だけ、H1以外は現在足と上位2足の計3足を確認する。同順位では波動一致数、副条件一致数の多い順とし、完全同順位では元の順序を維持する。

副条件9項目は次のとおり。

1. 現在足の最新Wave方向が分析方向と一致。
2. 現在足のポイントが補完ポイントでない。H1は成立扱い。
3. GMMA Trend CountがBUYで2以上、SELLで−2以下。
4. GMMA Cross CountがBUYで2以上、SELLで−2以下。
5. 現在足EMA200が分析方向と一致。
6. 上位2足目EMA200が分析方向またはNONE。H1は成立扱い。
7. 上位1足目EMA200が分析方向と一致。H1は成立扱い。
8. M5第3波のFEが有効な正数で、小数1桁に丸めて161.8%以下。それ以外は成立扱い。
9. Close[1]とEMA200[1]の絶対距離がH1で50 pips以下、それ以外で25 pips以下。

READYはAlert発生や発注の保証ではない。この表示用判定ではSpread・Signal Countなど実際のエントリー判定全体を評価しておらず、H1の上位EMA条件も上記のとおり成立扱いにしている。

### 7.2 D1条件ランク

| ランク | 条件 |
|---|---|
| D1-S | W1＝D1に加え、MN1とW1 EMA200の両方がD1方向 |
| D1-A | W1＝D1に加え、MN1またはW1 EMA200の片方がD1方向 |
| D1-B | W1＝D1だが、MN1・W1 EMA200はともにD1方向に不一致 |
| NG | W1とD1が不一致 |

D1専用ソートでは、評価済みを優先し、D1条件ランク、D1最新Wave、D1 EMA、W1最新Wave、W1 EMA、MN1最新Waveの順に方向一致ランクを比較する。その後ENTRY優先度で比較する。Waveは一致を優先、EMAは一致、NONE、逆方向の順。

### 7.3 H1専用ソート

評価済みを優先し、次の順に比較する。

1. D1条件ランク（S → A → B → NG）。
2. ENTRY判定足（H1直接一致 → H4代替）。
3. ENTRY優先度。
4. 波動一致数の降順。
5. 副条件一致数の降順。
6. D1最新Waveの方向一致ランク。
7. D1 EMAの方向一致ランク。

そのため、D1-AのREADYよりD1-SのNEARが上位になる場合がある。表示はD1条件ランクに加え、`H1 READY`や`H4 NEAR`等の判定足・状態を付記する。

### 7.4 M15専用ソート

CHARTのM15は5.6の4テーブルに分け、③・④ではEMA200がNONEの候補を逆方向の候補より前にまとめる。この分類とNONE優先は並び順の入力値にかかわらず適用する。

各分類内でM15専用ソートを選択している場合は、評価済みを優先し、M15最新Wave、M15 EMA、H1最新Wave、H1 EMA、H4最新Wave、H4 EMA、D1 EMAの順に多数派方向との一致ランクを比較する。Waveは一致を優先し、EMAは一致、NONE、逆方向の順。同順位では既存のENTRY優先度を使用する。完全同順位は元の順序を維持する。

ENTRY優先度を選択した場合も、4分類とNONE優先の後に既存の順位を適用する。M15専用ソートの多数派方向指定はこの4テーブルだけに適用し、従来の呼び出しはM15自身の分析方向を基準とする。

## 8. 更新・再試行・終了処理

| 実行環境 | 更新基準足 | 呼び出し |
|---|---|---|
| 通常チャート | M5 | `OnCalculate`および2秒間隔の`OnTimer` |
| テスター・一覧基準足がM5より上位 | 一覧基準足 | `OnCalculate` |
| テスター・一覧基準足がM5以下 | M5 | `OnCalculate` |

更新判定はホストシンボルの更新基準足の`iTime(..., 0)`を使用する。初回および新規バーで全対象を分析し、同一バーで毎ティック全分析は行わない。H1＋M5独立表示ではM5基準で両段を更新する。

分析が未完了の場合は、通常チャートではタイマー、テスターでは後続`OnCalculate`で同一バー最大3回再試行する。新規バーで再試行回数をリセットする。履歴準備待ちは分析バッチの再試行とは別に処理する。多重実行は`executing`で抑止する。

初期化時に対象シンボル・履歴を準備し、分析ハンドル管理器・判定器・描画器を作成する。タイマー設定失敗はERRORログへ記録するが、その理由だけでは初期化失敗にしない。

終了時はコントローラーを削除し、タイマー、描画オブジェクト、ハンドル管理器、判定器およびAlertコントローラー等を解放する。

## 9. テスター制約とAlert DB収集

### 9.1 一覧のテスター制約

| モード | テスト対象チャート足の制約 |
|---|---|
| D1固定 | D1以下 |
| H4固定 | H4以下 |
| H1＋M5独立2段 | M5以下 |

上表に違反する設定は`INIT_PARAMETERS_INCORRECT`。D1固定、H4固定、独立2段、およびDB有効のH1ではテスター履歴準備チェックを有効にする。分析用の必要履歴本数はMN1が61本、W1以下が206本を基準とする。これはAlert保存前に必要な連続評価5000本とは別の条件である。

### 9.2 DB収集の開始条件

DB収集はCHARTモードのH1・Strategy Testerのみで使用できる。最適化では使用不可。全28通貨を解決でき、ホストもその対象通貨であることを要求する。

- DBファイル名が空でなく、Commonフォルダ使用が`true`。
- Tester開始時刻が正の時刻。
- 連続評価開始がTester開始以降、DB保存開始より前。入力0はTester開始へ置換。
- DB保存開始がTester開始より後。
- 評価開始から保存開始までの経過時間が、最低WarmUp本数×1時間以上。
- 最終H1バー時刻がDB保存開始以降。
- 最低WarmUp本数は1～100000。
- 4種類の時刻がH1開始時刻として妥当。
- テスターモデルを`1 minute OHLC`に設定し、確認入力を`true`にする。

確認入力はテスターモデルを切り替える機能ではない。実際のモデル設定はテスター側で行う。単なる経過時間に加え、保存開始前の実際の連続評価本数もチェックするため、週末等を含む期間では余裕が必要になる。

### 9.3 一覧とAlertの条件の違い

一覧用の`d1AlignmentMode`・`h1AlignmentMode`・ソート指定でAlert条件は変更しない。Alertは`ZigZagElliotConfig.applyH1EntryPolicy()`を通して共通の`Mtf3In3H1Policy`を適用する。

| 項目 | Alertの共通固定設定 |
|---|---|
| 方向一致 | W1＝D1＝H4＝H1 AND（MN1＝H1 OR W1 EMA200がH1方向） |
| EMA確認 | H1・H4・D1のEMA200がH1方向に一致 |
| W1追加確認 | `OBSERVE_ONLY`。追加制限をせず診断記録 |
| 分析開始足 | MN1 |

波動・Spread・Signal Count等は実際の戦略判定に従う。`alertH1DisplayWaveEntryLimitEnabled`はH1表示波ごとのエントリー回数制限を切り替える。Listでは通貨強弱計算・エントリーフィルタ・順位表示を無効にする。また、メール検証ファイルとMTF_3in3 Alert CSV出力を無効にする。

28通貨を共通Runとして収集し、Alert発生時の情報を保存する。全時刻・全非成立候補を記録するObservation収集とは用途が異なる。重大な収集エラーまたは収集完了時は`TesterStop()`で停止する。保存テーブル等は[Alertデータベース仕様書](../Database/ZigZagElliotAlertDatabase.md)を参照する。

## 10. エラーと表示対象外の扱い

| 状態 | 処理 |
|---|---|
| バッファ設定失敗、必要オブジェクト生成失敗等 | 初期化失敗 |
| 非対応時間足、適用対象の不正な方向条件値、DB設定不正 | パラメーターエラー |
| 更新基準足の時刻が0 | その呼び出しでは処理しない |
| 必要な分析結果の不足 | 未準備として扱い、表示から除外・再試行対象とする |
| 方向一致条件の不成立 | 正常な表示対象外 |
| 必須D1 EMA200のNONE・不一致 | 正常な表示対象外。分析エラーとして数えない |
| M5の必須5足EMA200のNONE・不一致・不整合 | 正常な表示対象外。分析エラーとして数えない |
| M15のW1～M15 EMA200で逆方向＋正常なNONEが2足以上 | 正常な表示対象外。分析エラーとして数えない |
| M15のEMA200のフラグ競合・ラベル不整合・時間足不整合 | NONEとして許容せず表示対象外 |
| 一覧描画失敗 | ERRORログを記録。DB無効時は再試行対象にする |
| Alert収集の重大エラー | テスター停止 |

表示対象数が0でも、28通貨の分析が正常に完了していれば異常ではない。分析完了判定は対象数28、分析済み件数が対象数と一致、エラー数0を使用する。

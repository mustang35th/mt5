# ZigZagElliotMonitor：複数通貨監視・チャート自動表示の検討案

- 作成日：2026/11/18（JST）
- 状態：検討時の案を保存。2026/11/19に最小構成を実装
- 名称：`ZigZagElliotMonitor` は仮称
- 参照する現行仕様：ZigZagElliot v2.80、コミット `6be7cef`

この文書は、複数通貨ペアを監視し、エントリー条件が成立した通貨ペアを別チャートで開く機能の検討時の資料です。以下の監視方法・設定値・画面動作には未採用案も含みます。実装したGMO18通貨・M1の最小構成と初期値は [ZigZagElliotMonitor仕様](ZigZagElliotMonitor.md) を参照してください。

関連資料：[クラス図（検討案・2026/11/19）](ZigZagElliotMonitorClassDiagram.md)

## 目的と動作イメージ

1枚の監視用チャートから複数通貨ペアを分析し、条件を満たした通貨ペアの確認用チャートを自動で開きます。監視対象のチャートをあらかじめすべて開く必要がない構成を目指します。

例えば、EURJPYで今回のM1エントリー条件が成立した場合、EURJPY・M1を開き、ZigZagElliotなどを設定したテンプレートを適用します。

1. 指定した通貨ペアの価格・分析用履歴・通貨強弱を準備する。
2. 現行ZigZagElliotのM1判定を共用して、エントリー成立を確認する。
3. 同じ通貨ペア・時間足のチャートと、同じシグナルの表示履歴を確認する。
4. 新規表示の対象なら別チャートを開き、指定テンプレートを適用する。
5. 監視画面へ成立日時、売買方向、チャート表示結果を残す。

## 動作仕様の案

| 項目 | 案 |
|---|---|
| 監視対象 | 指定した通貨ペア、または既存の28通貨ペア |
| 監視時間足 | まずM1を対象とする。M5・M15などへの拡張は別途検討 |
| 成立条件 | 通常版ZigZagElliotのM1エントリー判定を共用 |
| 表示先 | 監視インジケーターと同じMT5内の別チャート |
| 開く時間足 | 成立した時間足。最初の案ではM1 |
| 初期表示 | 指定テンプレートでZigZagElliotなどを表示 |
| 既存チャート | 同じ通貨ペア・時間足が開いていれば新規作成しない。既存の表示設定は維持 |
| 重複防止 | 同じシグナルにつき1回。手動で閉じても同じシグナルで即座に開き直さない |
| 自動表示の上限 | 監視機能が開くチャートは最大5枚など。数値と上限到達時の動作は未決定 |
| 前面表示 | 「前面に出す／出さない」を選択可能とする案 |
| 監視画面 | 通貨ペア、監視状態、直近の成立日時（JST・SRV）、BUY/SELL、表示結果を一覧にする案 |

表示用テンプレートには、複数通貨を自動監視するインジケーターを含めない構成を想定します。新しく開いたチャートから監視処理が重複して起動することを防ぐためです。

## 共用したいM1エントリー条件

以下は検討の基準にする、現行v2.80の初期設定です。監視インジケーター側で条件を別実装してずれが生じないよう、既存判定の共用を基本案とします。

| 項目 | 現行条件 |
|---|---|
| 売買方向 | D1・M5・M1の元方向が一致 |
| 方向補正 | H4・H1・M15のうち逆方向1足まで補正可能。2足以上逆方向なら不成立 |
| 補正後の分析 | 補正した波動で再分析し、採用するD1～M1の方向と各条件を確認。再分析失敗は不成立 |
| エリオット波動 | M5・M1がそれぞれ主波の第1波または第3波。補正時は再分析後で判定 |
| M1の波方向 | BUYは上昇、SELLは下降 |
| GMMA | M1のトレンド・クロス両カウントが、BUYは＋2以上、SELLは−2以下 |
| ZigZag | M1の最新ポイントが追加途中ではない |
| 通貨強弱 | 長中期・中短期とも、BUYは順位差＋1以上、SELLは−1以下 |
| 順位差の増減 | 初期「両方」。長中期・中短期とも、BUYは上昇方向、SELLは下降方向 |
| スプレッド | 3 pips以下 |
| シグナル回数 | 同じシグナルの初回成立のみ |

順位差は「決済通貨順位 − 基軸通貨順位」です。増減はM5単位の順位履歴で判定し、横ばいでは直前の増減方向を維持します。データ不足・方向不明・対象時刻不一致では成立させません。

EMA200の方向・距離、M15の波動番号、FE上限、MN1・W1の方向一致はM1のエントリー条件に使用しません。現行M1のメール送信は無効です。

現行仕様の詳細は [ZigZagElliot.md](ZigZagElliot.md) を参照してください。

## 既存機能との関係

`ZigZagElliotList` には28通貨ペアの分析・一覧表示の基盤があります。ただし、以下の点で今回の監視機能とは異なります。

- 通常チャートではM5の新バーを基準に分析するため、M1チャートへ設置しても更新はM5単位。
- 一覧の抽出条件は、今回の通常版M1エントリー条件と同一ではない。
- 今回追加したM1の片足方向補正・両期間の通貨強弱増減判定には未接続。
- Alert収集機能はH1・テスター向けであり、LIVEのM1監視としては未対応。
- 条件成立時に別チャートを自動で開く処理は未実装。

既存の複数通貨処理を参考にしつつ、監視専用インジケーターを追加する案とします。M1の条件判定、通貨ごとの分析状態管理、チャートの起動・重複管理、一覧表示は役割を分けます。クラス構成の検討案は上記の関連資料にまとめ、具体的な配置やAPIは実装方針の決定後に確定します。

## 負荷を抑えるための案

- 通貨強弱の必要条件で候補を絞り、候補だけ波動分析へ進める。判定対象の時刻をそろえ、取得待ちと条件不成立を区別する。
- 全通貨を一度に再分析せず、通貨ごとに分割して処理する。
- 価格履歴、オシレーターハンドル、同じM5枠の通貨強弱情報を可能な範囲で再利用する。
- 重い分析はM1の新バーを基準とする案。必要なデータがそろわない場合の再確認は、現行M1判定との整合を優先する。
- 監視一覧は値が変わった行だけ更新する。
- チャートを開く処理は順番に実行し、同時成立で一度に多数のチャートが増えないようにする。

通貨数・履歴準備・補正再分析・テンプレート内のインジケーターによって負荷が変わります。分割処理には巡回の遅れも伴うため、処理時間と検出の遅れを測定して設定値を決めます。現時点では性能改善幅や全通貨の確認時間は未測定です。

## 実装前に決めること

| 検討項目 | 決める内容 |
|---|---|
| 対象通貨 | 28通貨すべてか、指定リストか。ブローカー固有の銘柄名・接尾辞をどう解決するか |
| 判定タイミング | M1新バー時を基準にするか。取得待ちの再確認間隔、巡回中の足交代をどう扱うか |
| 起動直後 | 起動時点ですでに条件成立中のペアも開くか、起動後の新規成立だけにするか |
| 初期設定 | 監視・自動表示・前面表示の初期ON/OFF、対象通貨数、表示上限 |
| テンプレート | 使用するファイルと設定。監視側と表示側のM1条件をそろえる方法 |
| 表示上限 | 上限の対象は監視機能が開いたチャートだけか。上限到達時は一覧のみか、待機させるか |
| 表示の優先順 | 複数通貨が同時成立した場合、成立順・通貨ペア順など、どの順番で開くか |
| 表示待ちの期限 | 上限・失敗で開けなかったシグナルを、いつまで有効な表示候補とするか |
| 重複管理 | シグナル識別方法、手動で閉じた場合、MT5再起動後、監視インジケーターを複数設置した場合の扱い |
| 監視の終了 | 監視停止・インジケーター削除時に、自動で開いたチャートを残すか |
| 失敗時の扱い | 履歴未取得、チャート起動失敗、テンプレート不在・適用失敗の表示と再試行 |
| 記録 | 成立履歴・表示履歴をメモリだけで保持するか、DBなどに保存するか |
| 対応範囲 | 最初は通常チャートでの監視に限定するか。テスターでは何を検証対象にするか |

## 実装後に確認する内容

- 同じ時刻・設定・入力データで、通常版ZigZagElliotと監視側のM1成立結果が一致すること。
- 方向補正、横ばいの増減継承、データ待機、欠損時の拒否が一致すること。
- 同じシグナルで繰り返し開かず、既存の同一通貨ペア・時間足チャートを重複作成しないこと。
- 手動で閉じた場合、上限到達時、起動失敗時の動作が決定した仕様に沿うこと。
- 指定した通貨ペア・時間足・テンプレートで表示され、監視元チャートが維持されること。
- 複数通貨の同時成立、データ到着の遅れ、分割処理中の足交代でも、古い判定を新しい成立として扱わないこと。
- 対象通貨数ごとの分析時間、巡回時間、MT5全体の応答性を確認すること。

## MT5の利用機能

銘柄・時間足を指定したチャート起動には [ChartOpen](https://www.mql5.com/en/docs/chart_operations/chartopen) を使用できます。起動成功時はチャートID、失敗時は0が返ります。MT5自体のチャート数上限もあるため、監視機能の上限内でも起動結果の確認が必要です。

表示用テンプレートは [ChartApplyTemplate](https://www.mql5.com/en/docs/chart_operations/chartapplytemplate) で適用できます。この関数の成功はチャートの処理キューへの受付を表すため、受付と表示完了を区別した扱いを検討します。

本資料の段階では、監視コード・チャート自動起動・テンプレート作成は行っていません。

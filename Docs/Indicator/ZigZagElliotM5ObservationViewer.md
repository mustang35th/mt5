## 2. 目的と初版の範囲

M5ごとの観測から「その時点で各時間足がどうなっていたか」「どの時点・品質で取得されたか」を確認する。1行は1通貨・1M5の保存済みObservationであり、エントリー候補や売買シグナルとは呼ばない。

初版で行うことは次の3点とする。

1. M5専用DBの観測を、Run・通貨・JST日時で検索する一覧。
2. 同じ観測のMN1／W1／D1／H4／H1／M15／M5を比較する詳細。
3. Spread、取得時刻、解析・取得時間、解析試行回数の表示。

初版では次を行わない。

- H1との一致を必須にした候補抽出、H1のFULL・ENTRY CHECKの適用。
- M5のエントリーOK／NG判定、新しい独自スコア・優先順位の算出。
- 上位足同期・EMA200一致などの複合条件検索。必要な条件は画面確認後に別途設計する。
- Episode化、将来損益・MFE・MAE、H1研究DBとの結合。
- 全ZigZagポイントによるチャート再現、保存されていない過去波の副次波判定。
- 通貨強弱の表示。M5 Observationには通貨強弱Snapshotがないため、Alert DBや現在値から補完しない。
- CSV出力、DB選択用のファイルブラウザー、DBの編集・削除・再収集。
- `/legacy/`へのM5機能追加。初版は標準React画面（`/`および互換URL `/react/`）を対象にする。

## 3. DB接続と画面入口

### 3.1 既存の接続先を維持する

現行の`--database`はAlert／H1の接続先であり、既定は`mstng-zigzag-elliot-alert.sqlite`である。現行`AlertDatabase.validate()`はアラート用テーブルを要求するため、M5の4テーブルDBを指定するだけでは利用できない。

| 接続 | 設計 |
|---|---|
| `--database` | 既存のAlert／H1用。意味・既定パスを変えない |
| `--m5-database` | M5専用DBのローカルパス。省略時はM5未設定。自動探索・別DBへのfallbackはしない |
| 同時利用 | 1つのViewerプロセスに独立した読み取り接続を持ち、タブで切り替える |
| 変更方法 | サーバー起動設定で指定し、変更時はViewerを再起動する。ブラウザから任意パスを渡さない |

初回の画面確認には収集済みの`Terminal\Common\Files\mstng-zigzag-elliot-m5-short-20260908-r3.sqlite`をM5接続先として指定する。Viewerによる閲覧は再収集と異なり、既存r3を読み取り専用で開いてよい。

日常のLIVE閲覧用には`start-m5-viewer.cmd`を使用する。接続先はCollectorの既定である`Terminal\Common\Files\mstng-zigzag-elliot-m5-observation.sqlite`、起動URLは`?tab=m5&sourceMode=LIVE`とする。専用起動ファイルが`--open-tab m5 --open-source-mode LIVE`を指定するだけで、4.1の指定なし時のTESTER既定値やCollectorの保存動作は変更しない。r3はテスト検証用として残す。

M5画面の上部には常に`M5 DB: ファイル名`を表示し、接続情報の展開で解決済みパス・接続状態・選択Run・分析Profileを確認できるようにする。Alert／H1のDB名と混同しない。

### 3.2 タブと起動時の動作

- 既存の「アラート一覧」「H1推移」に「M5推移」を追加する。
- M5未設定でもタブには設定案内を表示し、0件の収集結果とは区別する。
- M5の未設定・ファイル不在・形式不一致・一時読取失敗はM5内に表示し、既存Alert／H1を停止させない。
- `--m5-database`指定時は接続状態を個別に初期化する。M5だけが利用可能ならM5を初期表示し、既存タブにはその接続の利用不可理由を表示する。M5未指定の既存起動動作は維持する。
- 両方利用可能なら既存の初期タブを維持する。`tab=m5`指定があればM5を開く。
- 現行AppのAlert用health／Run／optionsの無条件取得を、画面・接続ごとの取得に分離する。M5から既存Alert APIを前提にしない。
- 既存の`127.0.0.1`待受・Host検証・Tailscale運用は変更しない。

### 3.3 読み取り専用と対応形式

- `mode=ro`、`query_only`、短い接続・読取トランザクションを使い、稼働中のWALを含む元DBを読む。
- DB作成、DDL、migration、索引追加、journal mode変更、checkpoint、WAL／SHMのコピー・削除は行わない。`immutable=1`は使わない。
- 収集側の厳密なDDL hash検査をそのまま移植せず、表示に必要なRun・親・子の必須列とM5用途を検査する。
- 初版で対応するRunはM5観測用`M5_OBSERVATION_ALL_V1`。観測は`anchor_time_frame=5`であることを必須とし、H1／Alert用途のRunや観測が混在するDBはM5接続先として受け付けない。未対応の識別・必須列不足は理由付きで利用不可とする。
- Runや観測が0件でも、対応するテーブル構成があれば「未収集」と表示する。Runの`status=LEGACY`や`completed_at=0`から収集完了・失敗を推測しない。
- 品質テーブル・品質行・個別列の有無は別の対応機能情報とする。品質がないだけで親観測を消さず、「未記録」を表示する。欠けをDBへ補完しない。
- 一時的な読取失敗は「更新失敗」と最終成功時刻を表示し、成功した0件レスポンスに置き換えない。キャッシュがある場合は古い表示であることを明示する。

## 4. M5推移一覧

### 4.1 初期表示と検索

M5の検索状態はH1と分離する。研究DBの確認を主目的とし、初回は`TESTER`・観測がある最新Runを選択する。最新Runは選択モード内で観測を持つRunのID降順から選ぶ。観測0件の新しいRunだけを自動選択して、過去の保存結果を隠さない。

初版は1つのRunを選んで表示する。複数Runを合算する「すべて」は設けない。0件Runも選択候補に件数付きで表示し、すべて0件なら最新Runを選ぶ。Runがない場合は「未収集」とし、一覧APIを呼び続けない。観測0件で初期日時を算出できない場合は日時未設定・0件表示とし、「最新24時間」を無効にする。日時が未設定の間は一覧検索を行わない。LIVEではmetadataの更新で最初の保存を検出でき、利用者が日時を未設定の場合だけ初期日時を設定する。TESTERが0件でもLIVEへ自動切替せず、利用可能なモードを案内する。

| 検索項目 | 仕様・初期値 |
|---|---|
| 実行モード | `TESTER`／`LIVE`。初期値TESTER。切替時はそのモードのRunを選び直す |
| Run | 必須の1件。ID、program version、保存期間、観測件数で識別できるようにする |
| 通貨 | 全通貨または1通貨。候補は選択Run内の保存済み通貨から取得 |
| JST日時範囲 | 初回は選択Run全体の最終M5開始JST＋5分を終了とする直近24時間を設定。以後は利用者が変更可能 |
| JST時刻 | 未指定または`HH:mm`。分は00／05／10／…／55。複数日の同じ開始時刻を調べる条件 |
| 件数 | 初期50件。50／100／200件から選択 |
| 並び順 | 初期はJST日時降順。JST日時・通貨の昇順／降順だけを初版の全体ソートとして許可 |

日時範囲はM5の開始時刻に対する`開始以上・終了未満`とし、入力欄にも「終了は含まない」と表示する。5分境界のJST日時を受け付け、終了≦開始などの不正値は検索前に案内する。保存済みJST値を使い、ブラウザのタイムゾーンで再変換しない。毎日同時刻の検索は日時範囲と併用する。

初期日時の例：r3は最終M5開始JSTが`2026.09.09 05:55`なので、`2026.09.08 06:00以上～2026.09.09 06:00未満`となり、1日分の8,064件を表示対象にできる。

「最新24時間」ボタンは選択Run全体の最新観測のM5開始JSTから上記の日時を再設定して検索する。TESTERでは固定範囲として扱う。LIVEでは初期表示と同ボタン操作時に最新追従を有効にし、その間だけ更新ごとに範囲を進める。手動の日時変更・過去ページ参照・最新日時降順以外のソートでは最新追従を解除する。現在のPC日時を基準に研究DBを空表示にしない。

明示的なモード・Run切替では1ページ目と初期日時へ再設定する。同じRunへの画面復帰やURLからの検索復元では、利用者が指定した期間を維持する。

検索はボタンで適用し、入力途中の条件と適用済み条件を区別する。条件・ソート・件数変更時は1ページ目へ戻す。ページ番号の直接入力、Enter／移動、前へ／次へを用意し、0件・読込中・範囲外の入力は無効にする。

### 4.2 一覧の情報配置

上部は「接続DB・Run」→「検索条件（開閉可能）」→「適用中の条件・検索件数・最新観測のM5開始JST・更新操作」の順とする。一覧下部にページ操作を置く。件数はフィルターに一致する保存済み観測数であり、収集予定数・未保存数ではない。

| 列 | 標準表示 |
|---|---|
| M5開始JST | 分まで表示。ツールチップで保存済みServer時刻も確認 |
| 通貨 | 通貨ペア名 |
| M5分析方向 | M5子行の`is_buy`からBUY／SELL。未記録・不正値は不明 |
| MN1／W1／D1／H4／H1／M15／M5 | 7つの概要セル。分析方向、Elliott／副次波ラベル、EMA200方向をコンパクトに表示 |
| Spread | 観測時の保存値、単位pips |
| 取得品質 | 市場取得遅れ、解析時間、取得時間、解析回数の短縮表示。詳細な意味はツールチップ |
| 詳細 | 対象Observationを開く |

JST・通貨・M5分析方向を左、詳細を右に固定し、横スクロールを許可する。狭い画面では固定を解除する既存挙動を使う。文字を極端に縮めて7足を無理に収めない。列表示・順序・幅、標準／コンパクト表示をM5用設定として保存する。

- M5の代表方向はM5自身の分析方向であり、H1の方向ではない。H1と反対でも表示する。
- 分析方向とWave方向は別の保存項目である。BUY／SELLの文字と波動の▲／▼を混同しない。
- BUY／SELLは既存の意味色と文字を併用する。色だけで判別させず、H1との一致を理由に行全体を候補色へ変更しない。
- EMA200はBUYのみ／SELLのみ／NONE／両方向成立を区別する。フラグ欠けは未記録。現行ProfileのMN1 EMA200は「対象外」でありNONEとは分ける。
- M5にH1の`FULL BUY`／`FULL SELL`バッジやENTRYラベルを出さない。
- ソートはサーバー側で実施し、同値時の順序も固定する。日時は`anchor_jst_time`と`id`を同じ昇降順、通貨は指定昇降順の後に日時降順・ID降順とする。現在ページだけを並べ替えない。
- 行・詳細・キャッシュの識別にはM5接続元とObservation IDを併用する。別DBで同じ数値IDがあってもH1の詳細やキャッシュへ接続しない。

## 5. 詳細画面

### 5.1 表示順と前後移動

一覧から既存と同様のDrawerを開き、最初に比較表示を出す。

1. 通貨、M5開始JST／Server、M5分析方向、Spread、Run、前後移動。
2. `TIMEFRAME COMPARISON`：7時間足の比較。
3. `CAPTURE QUALITY`：取得品質と時計の説明。
4. `RECORD INFO`：折りたたみ式の保存情報。

閉じたときは一覧の条件・ページ・スクロール位置を維持する。詳細の前後移動は、同じDB・Run・通貨・実行元・分析Profile・M5アンカー内の直前／直後の保存済み観測とする。一覧の日時範囲・時刻条件は適用せず、詳細には「同一Run・通貨の前後観測。一覧の検索範囲外へ移動する場合あり」と表示する。

隣が存在しない場合は移動不可とし、5分後に観測がなくても作成・補間しない。5分を超える場合は実際の時刻差を表示するが、休場か欠損かをDBだけで断定しない。表示中の観測を自動更新で別IDへ差し替えない。連続クリック・タブ移動では古い応答を破棄する。

### 5.2 TIMEFRAME COMPARISON

既存の比較グリッドを基本に、行をMN1→W1→D1→H4→H1→M15→M5の順に固定する。M5だけに「基準足」を表示する。標準表示と折りたたみの詳細項目を分ける。

| 分類 | 表示内容 |
|---|---|
| 標準比較 | 分析方向、Elliott／副次波、Wave方向・確定／形成中・推進／修正、ZigZag通常／追加ポイント、EMA200、GMMA、Stochastic、ATR |
| 最新ZigZag Point | 最新点JST／Server、価格、Peak／Bottom、経過本数、pips差、F／FE、Depth Zone、元番号・補正情報 |
| OHLC | 直前確定足と取得時点の形成中足のOpen／High／Low／Close |
| 指標詳細 | 保存済みEMA200位置・傾き・距離、Stochastic各線、GMMA Count、FE価格など |

F／FEは既存の保存値・元Elliott番号による表示規則を使い、未記録や利用不可を0%としない。MN1 EMA200の計算省略も明示する。価格差の換算は保存済み`pip_size`を使い、現在の価格や別通貨の値を参照しない。

「現在足OHLC」は取得時点の途中経過であり、後に確定したM5／上位足のOHLCとは限らない。Waveの「確定」も保存時点の状態を表し、将来の再分析で変わらないことを保証しない。

子行が欠ける場合は7行の枠を保って該当足を「未記録」とし、足構成の不足を表示する。重複・不正な足ID／順序／基準足も要確認とし、正常な7足として数えない。保存されていない波動履歴・過去第3波の副次波などを最新点から推測表示しない。

### 5.3 CAPTURE QUALITY

| 表示名 | 元データ・計算 | 意味 |
|---|---|---|
| 採用気配時刻（Server、ms） | `quote_tick_time_msc` | Spread計算に採用した気配の更新時刻 |
| 取得市場時刻（Server） | `capture_market_time` | Snapshot確定時の市場時刻。TESTERでは模擬時刻 |
| 市場取得遅れ（秒） | `capture_market_time - anchor_bar_time` | M5開始から取得市場時刻までの差。通信遅延・実処理時間ではない |
| 解析時間（ms） | `analysis_elapsed_ms` | 最後に成功した解析1回の実経過時間 |
| 取得時間（ms） | `capture_elapsed_ms` | 当該M5の初検出からSnapshot確定までの実経過時間 |
| 解析回数 | `analysis_attempt_count` | 観測用の実解析回数。事前分析・履歴確認だけ・DB再送は含まない |

品質時刻はServerと明記して原記録を表示する。M5開始JST／Serverを同じカードに併記して比較できるようにし、品質時刻をPCの現在時刻へ読み替えない。初版では品質時刻の独自JST変換を追加しない。

- 解析時間はDB書き込み時間を含まない。取得時間は初検出後の待機・再試行・Snapshot生成を含むが、FIFO追加後のDB保存待ちは含まない。「保存時間」と呼ばない。
- 品質テーブルなし、品質行なし、個別値NULLを区別して理由を表示する。有効な`0ms`・遅れ`0秒`はそのまま表示する。
- `created_at`を品質値の代用にしない。過去の品質を推測補完しない。
- 負の差は負値のまま「時刻逆転・要確認」、気配が対象M5より前なら「過去の気配」、取得市場時刻が対象M5外なら「対象足外」と表示する。0へ丸めない。
- 任意の遅延しきい値でデータを自動除外・売買NG判定しない。品質は保存状況の参考表示であり、28通貨同時取得・収集全体の完全性を保証しない。

### 5.4 RECORD INFO

接続DB名、Observation ID、Run ID／UID、source mode、取引サーバー、program version、strategy／analysis version、analysis input hash、snapshot hash、capture phase、pip size、記録作成日時（`created_at`）を確認できるようにする。長いhashは省略表示と展開・コピーを用意する。

`created_at`はFIFO追加前のSnapshot生成時に固定する値であり、DB commit完了時刻・収集終了日時ではない。初版では口座番号などの追加表示を行わない。H1 ENTRY CHECKと通貨強弱カードはM5詳細に置かない。

## 6. APIと実装境界

### 6.1 API

| メソッド・パス | 用途 |
|---|---|
| `GET /api/m5/metadata` | M5接続状態・DB識別情報・対応機能・モード別Run候補・選択Runの通貨／保存期間／分析Profile |
| `GET /api/m5/observations` | 検索条件に合う件数・ページ情報・親行・ページ内7足概要・品質 |
| `GET /api/m5/observations/{id}` | 親、7足詳細、品質、保存情報、同一Run等に限定した前後移動 |

既存`/api/observations`およびAlert APIの意味・レスポンスは変更しない。M5 APIはM5接続だけを参照し、ID不在でも他DBを探さない。

- metadataは`sourceMode`（省略時TESTER）と任意の`runId`を受ける。Run未指定時は4.1の規則で選び、`effectiveRunId`とそのRunの保存期間・通貨等を返す。Runがない場合はID・期間をnullとする。指定Runが不在なら404、モード不一致なら400とし、別Runへ自動fallbackしない。
- 初回とモード切替ではRun未指定のmetadataを取得してから、選択結果と初期日時で一覧を検索する。明示的なRun切替はそのIDでmetadataを取得する。検索状態を復元できる場合は利用者の期間を維持するが、DB識別情報が変わった場合は旧Run・詳細IDを破棄して初期選択からやり直す。
- 一覧パラメータは`sourceMode`、`runId`、`symbol`、`from`、`to`、`jstTime`、`page`、`pageSize`、`sort`、`order`。`runId`必須、モードとRunの整合も検証する。
- `from`／`to`はJSTの5分境界の日時、`jstTime`は5分刻みの時刻。初版は日時範囲を必須とする。時刻・日時の検証はH1の`HH:00`固定処理と分ける。
- 日時・通貨などを検証してbind parameterで渡す。ソート・時間足の識別子は許可リストに限定し、任意のSQLやDBパスを受け付けない。
- H1用`groupMode`、`fullAlignment`、`syncTimeFrame`等を受け取った場合は、M5の一覧APIでは400として理由を返す。黙ってH1判定へ進めたり無視したりしない。
- 一覧・件数・詳細・前後移動すべてにM5用途と`anchor_time_frame=5`を適用する。詳細ナビゲーションではRunと分析Profileも必須条件にする。
- metadataは未設定・未収集・形式不一致を状態と理由付きで返す。不正検索は400、対象ID不在は404、DBの一時読取失敗は503とし、0件と区別する。
- 品質は`captureMetrics`の各値をnullableで返し、テーブル／行／列の記録状態を別途返す。欠けた品質によって一覧から親観測を落とさない。
- 件数・ページ・親・子・品質は同じ短い読取トランザクション内で取得する。LIVEで別タイミングの結果を組み合わせない。
- 任意の`databaseKey`で接続元を確認でき、不一致は409とする。詳細画面は必ずキーを送信する。一覧も応答キーがmetadataと一致しなければ結果を採用しない。
- 接続のSQLite待機は5秒、SQL実行には10秒の上限を設ける。タイムアウトは503で検索期間を狭める案内を返し、0件へ置換しない。

### 6.2 流用と分離

| 対象 | 方針 |
|---|---|
| DBアクセス | M5専用の読み取りクラスとvalidatorを追加。Alertの必須テーブルやH1固有の検索条件から分離 |
| App／API client | M5用の接続状態・Run・検索・詳細の取得先を追加。既存API失敗へM5を巻き込まない |
| 検索・一覧・Drawer | M5専用の薄いView／state／Table／Drawerを追加。H1のFULL計算やENTRY表示を持つコンポーネントをそのまま再利用しない |
| 比較・部品 | 価格・波動のformatter、EMA200バッジ、ページ番号入力、汎用グリッド・表示部品を流用。共有部の既定値はH1の5足を維持 |
| 設定保存 | `m5Observation.*`の独立した名前空間。列設定、比較列、表示密度、更新間隔をH1と混在させない |
| URL／画面状態 | `tab=m5`とM5専用parserを使用。Run・観測IDは接続DB識別情報と結び付け、別DBへの切替時に詳細・キャッシュを破棄 |

既存[ObservationDetailDrawer](../../Services/ZigZagElliotAlertViewer/frontend/src/components/ObservationDetailDrawer.tsx)はH1 ENTRY CHECKを表示し、[ObservationTable](../../Services/ZigZagElliotAlertViewer/frontend/src/components/ObservationTable.tsx)は5足・FULL判定を前提にする。[observationSearchState](../../Services/ZigZagElliotAlertViewer/frontend/src/lib/observationSearchState.ts)もH1の時刻・Episode条件を持つため、名前だけM5へ変える実装は行わない。

## 7. 更新・性能・整合性の注意

- TESTERは手動更新。LIVEのみOFF／5／15／30／60秒から選択し、初期15秒。M5用設定として保存する。
- 非表示タブ・非表示ウィンドウでは自動取得を止め、戻ったときに確認する。詳細閲覧位置を勝手に移動しない。
- 最新日時降順の1ページ目・最新追従中だけ新しい範囲を反映する。それ以外は固定範囲・ページを保ち、新着案内と「最新24時間」で明示的に戻す。
- 自動更新で選択Runを別Runへ切り替えない。新しいRunを検出した場合は切替案内を出し、利用者が選択する。
- 同じ問い合わせを並列に積み上げない。古いリクエストを中止し、応答時に接続元・検索条件・詳細IDが一致するか確認する。
- 親の検索・COUNTを先に行い、子と品質はページ内の親IDをまとめて取得する。7足JOINによる親の7重計数やN+1クエリを避ける。
- 既存のJST・モード・通貨・Profile・Run索引、子の親ID／時間足索引、品質PKを利用する。時刻だけの全期間走査を避け、日時範囲と併用する。
- 全件をブラウザへ読み込まない。深いページ・広い期間での応答時間は実装時に計測し、タイムアウト時は範囲を狭める案内を出す。根拠のない応答時間保証や隠れた件数打切りは行わない。
- 収集側はスキーマの厳密な検査を行うため、性能対策としてViewerが索引を追加することも禁止する。追加索引・大規模集計は別の設計変更とする。
- ViewerからCollectorのメモリ内Queue・Gap・保存ゲート・終了状態は取得できない。DB最新時刻だけから「収集稼働中」「収集完了」「欠損なし」と表示しない。

## 8. 実装順序と受け入れ条件

### 8.1 実装順序

1. M5読み取り接続・対応形式検査・metadata・起動時の個別接続状態を実装する。
2. M5専用の検索／一覧APIとタブ・検索フォーム・ページングを実装する。
3. 7足比較・取得品質・前後移動・保存情報の詳細を実装する。
4. M5設定保存・LIVE更新・エラー／未記録表示を確認する。
5. 専用fixtureでAPI／UI回帰テストを行い、r3を読み取り専用で開いて表示を確認する。

### 8.2 受け入れ条件

| 分類 | 確認すること |
|---|---|
| 接続分離 | 既存`--database`・Alert／H1を維持。M5接続の失敗を他タブへ波及させない。M5だけ利用可能な場合もM5を開ける |
| DB保護 | 存在しない指定先を作らず、H1／混在／未対応DBを拒否。閲覧によるDDL・データ更新・checkpointなし |

| ページ | 50件表示では8,064件は162ページ、最終14件。直接入力・ソート・条件変更・0件・範囲外を確認 |

### 8.3 初版の実装・確認結果（2026-09-10）

`m5_observations.py`にM5専用の読み取り接続・形式検査・metadata／一覧／詳細を追加した。`app.py`のM5 APIと`--m5-database`は既存接続から分離し、M5-only起動とAlert／H1側のエラー表示にも対応した。`start-viewer.cmd`の既存プロセス確認はM5-onlyも検出する。設定例は[README](../../Services/ZigZagElliotAlertViewer/README.md#m5推移の起動使い方)を参照する。

React側にはM5専用View／Table／DetailDrawer、検索状態・API client・表示設定を追加した。比較は7足固定の表と横スクロール、追加詳細の展開ボタンを使用し、H1 ENTRY CHECK付きの比較部品へM5を渡さない。列幅・順序・表示密度・更新間隔・比較展開状態をM5用のキーに保存する。

| React／TypeScript | 全28ファイル・265テスト、型検査、production build成功。既存回帰、M5検索・DB切替・古い応答破棄・品質・7足詳細・設定保存を確認。実AG Gridのソート・列固定切替はjsdom内で検証 |
| r3 metadata | TESTER Run 1、28通貨、対応状態READY |

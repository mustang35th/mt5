# MstngM5Ea

## 対象と構成

`Experts/MstngM5Ea.mq5` はM5チャートに設置する単一通貨EAです。通常版 `ZigZagElliot` のM5設定を `Mtf3In3M5Policy` で共用し、既存の `ExpertAdvisorMtf3In3M5` を直接呼び出します。発注・broker照合・SL保護・取引状態復元は `MstngEaCommon` の `EaTradeExecutor`、初期SLは `EaInitialStopLossDecision`、回数管理は `EaEntryState` を使います。

M5固有の設定・Controller・Strategy・保存処理は `Include/MstngM5Ea` に置きます。既存H1・M15 EAの注文処理と保存形式は変更しません。既存基盤と同じhedging口座を対象とし、最適化は未対応です。

## 入力

| 入力 | 初期値 | 内容 |
|---|---:|---|
| 固定ロット | 0.01 | brokerの最小・最大・stepに合わせて正規化 |
| 最大初期SL幅 | 100.0 pips | 正値必須。上限を超える場合は見送り |
| 初期SLの余白 | 10.0 pips | 既存M15 EAと同じ初期値 |
| M5トレーリングの余白 | 10.0 pips | 初期SLと独立して指定 |
| 通貨強弱をエントリー条件に使用 | ON | 長中期・中短期の順位条件を使用 |
| 順位差基準 | 4 | 1～7。各期間は方向に合う1位・8位でも通過 |
| 長中期の増減方向 | ON | M5履歴の増減を確認。横ばいは直前の方向を維持 |
| 通貨強弱DB名 | mstng-currency-strength.sqlite | 既存の通貨強弱DBを参照 |
| 年別DB／Commonフォルダ | ON／ON | 通常版と同じ初期値 |
| 参照元／集計方式 | LIVE優先・TESTER補完／加重 | 通常版と同じ初期値 |
| テスター売買開始日時 | 2026.01.01 00:00 | サーバー時刻。0は制限なし。LIVEでは不使用 |

通貨強弱の取得間隔は15秒、LIVEのEntry判定は初回1秒後・以後30秒です。H1表示波ごとの回数制限は通常版の初期設定と同じOFFに固定します。

## M5の判定条件

- D1とM5の元方向一致を必須とし、H4・H1・M15の逆方向1足だけを補正します。補正後のD1～M5の方向を確認します。
- 採用したM15・M5の主波は、それぞれ1または3です。副次波だけの一致では通過しません。
- H1・M15・M5のEMA200方向一致、M5の波方向・ZigZag確定・GMMA Trend/Cross条件を確認します。EMA200距離上限は使用しません。
- M5第3波のFEは有効な正値かつ小数1桁で161.8%以下、スプレッドは5pips以下です。
- 通貨強弱ONでは長中期・中短期の両方が売買方向と一致し、各期間で順位差基準、または方向に合う1位・8位を満たす必要があります。長中期の増減ONではBUYは増加、SELLは減少を要求します。
- 元M5の第2ポイント時刻と方向で回数を管理し、初回シグナルだけをEntry対象にします。

チャート上の矢印やメール文字列は読み取りません。同じ判定クラスに分析・通貨強弱・設定を渡します。判定時刻や価格系列、DBデータが異なる実行同士は結果が変わり得るため、一致確認ではそれらも揃えます。

## 判定周期とデータ待ち

各M5バーで最初に分析と必要データが揃った判定を確定します。分析不能・現在M5の順位未取得・必要な順位差履歴の取得待ちは同じM5内で再試行し、回数を消費しません。方向不明や条件不一致は見送りです。判定中にバーや気配が失効した場合も確定前に戻ります。

取得待ちのまま次のM5へ進んだ場合は前バーを見送りとして記録し、前バーの遅延発注は行いません。初回成立後の保有制限・SL不適合・保存失敗による見送りは既存EAと同じ消費済みシグナルとして記録します。

通貨強弱DBには対象時刻の順位データが必要です。バックテストも同じ対象期間のデータを参照し、欠損時に別のM5枠の順位で代用しません。既存Providerと同じM5時刻単位の取得であり、そのバー内で順位が記録された実時刻まで再現するものではありません。LIVE／TESTERの参照元・集計方式はインジケーターと合わせて指定できます。

テスターでは既存Providerが同一M5の取得結果をキャッシュします。欠損後にそのM5のデータを追記しても同じ枠では再取得しないため、テスト開始前に対象期間の通貨強弱DBを用意してください。

v1.01ではテスターの売買開始前の安全な空状態だけ、Timer・Lease更新・保存保守を30秒周期へ切り替え、Tickでは履歴準備と低頻度保守だけを行います。DB正常・復元完了・排他とLease有効・監査欠落や保存待ちなし・Executorの空状態照合済み・口座全体の保有と注文なしが条件です。Leaseの有効期限60秒は変更しません。

開始日時への到達や安全条件の不成立で通常の1秒Timerへ戻します。復帰失敗時はEntryを止め、Tickによる既存取引の保護を続けながら最短5秒後に再試行します。履歴待ちログは準備中だけ、内容変更時は最短1時間、同一内容は1日間隔にまとめます。売買開始後のM5ごとの診断は維持します。

## 注文・SL・復元

自EAの同一通貨1ポジションを管理します。初期SLには方向補正後に採用したM5の第2ポイントを使用し、重複防止の元分析キーと分離します。brokerの価格刻み・SL最小距離・最大初期SL幅を検証します。

保有中は通常のM5分析の確定ZigZagからトレーリングします。通貨強弱の取得待ちによってSL管理を止めないよう、トレイル分析はEntry分析から独立しています。新しい固定TPやGMMA反転決済は追加せず、既存EAのSL保護方式を継承します。

Decision・Trade・ENTRY_REQUESTを同一transactionで保存できた場合だけ共通Executorへ送信を依頼します。判定成立、実発注の可否、見送り理由を分けて保存します。保存再試行は見送り監査の保存だけで、遅延発注へ変換しません。

| 識別 | M5専用値 |
|---|---|
| LIVE DB | Common Filesの `mstng-m5-ea.sqlite` |
| Tester DB | Common Filesの `mstng-m5-ea-tester.sqlite` |
| テーブル | `m5_ea_runs`・`m5_ea_decisions`・`m5_ea_trades`・`m5_ea_trade_events` |
| schema | v1、Run時間足5、同バー判定は300秒単位 |
| Magic | EAコード14＋シンボル＋M5＋MTF_3in3 |
| 排他／運用ログ | `MstngM5Ea/Locks`／`MstngM5Ea/Logs` |
| 復元context | `M5_EA_CONTEXT_V1`。LIVEは口座・通貨・Magicごと、TesterはRunごと |

再起動時は消費回数、当該M5バーの確定判定、未完了取引、pending SL、決済意図を復元します。EAを終了しても建玉とbrokerへ設定済みのSLは残します。

`JUDGMENT_ANALYSIS_UNAVAILABLE`の1,061件は、すべて元分析を取得済みで採用分析がない状態でした。内訳はD1とM5の不一致728件、H4・H1・M15の逆方向が2足257件・3足76件です。この理由名は正常な不採用と補正失敗を分離していないため、元分析の失敗件数としては扱いません。今回、理由コードの変更はしていません。

### データ品質と比較上の制限

標準レポートの実ティック品質は10%です。これは2021年からのウォームアップを含む全期間の値で、実ティックの使用期間はログ上2026.02.10～09.11でした。実ティック欠損は2月10日の140分、評価対象の9月7～11日は欠損警告0件です。ただし、対象週だけの品質が100%であるという独立した測定はしていません。

テスターで見える履歴は2020年からで、通常チャートが参照する全履歴とは異なり得ます。事前保存済みの通貨強弱順位が実際に到着した遅延も再現していないため、今回の成績はこの履歴・DB・設定による単一通貨1週間の結果です。

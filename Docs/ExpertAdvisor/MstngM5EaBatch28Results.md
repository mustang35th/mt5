10018はMarket closedです。SL変更が拒否されたイベントは、以前のSLが保持されたことを照合し、変更成功件数へは含めません。決済拒否は再試行・最終決済と併せて記録します。

公式定義: [Trade Server Return Codes](https://www.mql5.com/en/docs/constants/errorswarnings/enum_trade_return_codes)。

PFは標準HTMLの値を転記しています。損失取引がないUSDCADでも0.00と表示されるため、PFだけで比較せず取引数・損益と併せて参照してください。

全28実行でSTOPPEDとネイティブログの完走を確認しました。DBの保存・参照、時間範囲、要求と結果の対応、初期SLとリスク、SL変更、重複、未完了取引、外部キー、SQLite quick_checkの監査エラーは0件です。102取引はすべてCLOSED、拒否された新規注文2件はOPEN_FAILEDです。標準HTMLの完了取引数・純損益がDBと一致しました。

## 実行手順で確認した点

USDJPYは起動設定方式、以降27ペアはログインを維持したGUIで順次実行しました。端末再起動でワンタイム認証が再要求されるため、無人連続起動の仕組みとしては完成していません。途中で止めたEURJPYのCLI試行は本集計に含めていません。

今回のbuildではUTF-8 BOMのINIをGUIで読み込んでも設定が変わらず、UTF-16 BOMでは銘柄・期間が反映されました。準備スクリプトの出力をUTF-16 BOM・CRLFへ変更し、28ファイルで設定と13入力の維持を検査しました。既存のBatch28-01プリセットは証跡として残し、新形式の検証用出力はBatch28-Utf16Verifyへ保存しました。端末はMstngM5Ea・CADCHF・元の準備期間へ戻し、テスター停止状態で残しています。

`JUDGMENT_ANALYSIS_UNAVAILABLE`は判定用分析を採用できなかった分類です。現行コードではD1〜M5の方向条件で判定対象外となる場合もこの分類に入るため、29,029件すべてを価格履歴の読込失敗とは扱いません。方向不一致と分析失敗の内訳はこのコード単独では区別できず、細分化は今後の候補です。

`CURRENCY_STRENGTH_WAIT_EXPIRED`25件はすべて9月7日00:00枠でした。事前検査で直前の週末枠が存在しないことを確認しています。現在枠の順位データ欠損とは分けて記録します。`ENTRY_ACCEPTED`104件は発注判定の受理であり、実際の約定成功を意味しません。うち2件は市場休止で拒否され、完了取引は102件です。
